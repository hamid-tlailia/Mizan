# ميزان الحديث

أداة بحثية عربية لفحص وتخريج الأحاديث، مبنية بواجهة React + tRPC + Express، وتُنشر على Vercel.

## الرابط المباشر

**https://mizan-hadith.vercel.app**

مبني وينشر تلقائياً من فرع `main` عبر Vercel (`vercel.json` + `api/index.js`، انظر التعليق أعلى `server/_core/vercelApp.ts` لتفاصيل كيفية حزم دالة الـ API).

## التشغيل محلياً

```bash
pnpm install
pnpm dev      # يشغّل الخادم والواجهة معاً على http://localhost:3000
pnpm test     # الاختبارات
pnpm run check  # فحص الأنواع
pnpm run build  # بناء إنتاجي (خادم Node تقليدي، وليس Vercel)
```

## متغيرات البيئة

| المتغير | إلزامي؟ | الوصف |
|---|---|---|
| `BUILT_IN_FORGE_API_KEY` | لتفعيل فحص الحديث | مفتاح API متوافق مع OpenAI |
| `BUILT_IN_FORGE_API_URL` | اختياري | نقطة نهاية بديلة (افتراضياً `https://forge.manus.im`، غير متاحة خارج منصة Manus — استخدم `https://api.openai.com` مع مفتاح OpenAI حقيقي، أو أي خدمة أخرى متوافقة) |
| `LLM_MODELS` | اختياري | قائمة نماذج مفصولة بفواصل تُجرَّب بالترتيب عند نفاد حصة أحدها (انظر أدناه) |
| `DATABASE_URL` | لتفعيل قاعدة البيانات | رابط اتصال MySQL |
| `JWT_SECRET`, `OAUTH_SERVER_URL`, `OWNER_OPEN_ID` | لتسجيل الدخول | إعداد Manus OAuth (انظر ملاحظة القسم الخاص بقاعدة البيانات) |

تُضبط هذه المتغيرات من Vercel → Project Settings → Environment Variables، ثم Redeploy.

## 1) الحصول على مفتاح ذكاء اصطناعي والتبديل بين النماذج

### أ. الحصول على مفتاح OpenAI

1. أنشئ حساباً على **platform.openai.com** (أو سجّل الدخول إن كان لديك حساب).
2. من القائمة الجانبية اذهب إلى **Billing**، وأضف وسيلة دفع وحدّاً للإنفاق الشهري (بدون رصيد فعّال، ستفشل كل الطلبات بخطأ حصة حتى لو كان المفتاح صحيحاً).
3. اذهب إلى **API keys** (platform.openai.com/api-keys) واضغط **Create new secret key**.
4. انسخ المفتاح فوراً — لا يمكن رؤيته مرة أخرى بعد إغلاق النافذة.
5. في Vercel: أضف `BUILT_IN_FORGE_API_KEY` بقيمة هذا المفتاح، و`BUILT_IN_FORGE_API_URL` بقيمة `https://api.openai.com`.
6. أعد النشر (Redeploy) من لوحة Vercel.

> يمكن استخدام أي خدمة أخرى متوافقة مع صيغة OpenAI لطلبات `chat/completions` (مثل Groq أو Together AI أو نقطة نهاية ذاتية الاستضافة) — فقط بدّل `BUILT_IN_FORGE_API_URL` واسم النموذج في `LLM_MODELS` أدناه.

### ب. التبديل التلقائي بين النماذج حتى لا تنفد الحصة

التطبيق يدعم تجربة أكثر من نموذج بالترتيب: عند فشل نموذج بخطأ **429** (تجاوز الحصة أو حد المعدل) يُجرَّب النموذج التالي تلقائياً دون أن يفشل طلب المستخدم — هذا منطق موجود فعلاً في `server/hadithAnalysis.ts` (دالة `invokeWithModelFallback`) ومُختبر في `server/hadithAnalysisFallback.test.ts`.

اضبط المتغير `LLM_MODELS` بقائمة نماذج مفصولة بفواصل، من الأرخص/الأوفر احتياطياً إلى الأساسي، أو العكس حسب أولويتك، مثال:

```
LLM_MODELS=gpt-5,gpt-4.1-mini,gpt-4o-mini
```

- إن لم تُضبط، يُستخدم `gpt-5` فقط (بلا احتياطي).
- الفشل غير المتعلق بالحصة (طلب غير صالح، مفتاح خاطئ، انقطاع شبكة) **لا** يُجرَّب فيه نموذج آخر — يُعاد الخطأ فوراً لتجنّب إخفاء مشاكل حقيقية.
- إن نفدت حصة كل النماذج في القائمة، يظهر للمستخدم خطأ عربي واضح يطلب إضافة نموذج بديل أو مراجعة الرصيد.

### ج. السرعة مقابل الجودة

نماذج التفكير (Reasoning) مثل GPT-5 تستخدم افتراضياً جهد تفكير **متوسط (medium)**، وهو ما يجعلها بطيئة نسبياً لمهمة مقيّدة كهذه. التطبيق يطلب تلقائياً `reasoning_effort: "low"` من أي نموذج يدعم هذا الحقل (تراجع تلقائي بلا هذا الحقل للنماذج التي لا تدعمه، دون أن يُحسب ذلك فشلاً أو ينتقل لنموذج آخر في `LLM_MODELS`) — هذا يسرّع الاستجابة ملموساً مقابل تفكير أقل عمقاً.

إن كانت النتائج لا تزال بطيئة أو غير دقيقة بما يكفي لديك:
- **للسرعة قبل كل شيء**: ضع نموذجاً غير-تفكيري خفيفاً أولاً في `LLM_MODELS`، مثل `gpt-4.1-mini` أو `gpt-4o-mini` — أسرع بكثير من أي نموذج تفكير، لكنه أقل دقة في تحليل نصوص شرعية دقيقة.
- **للدقة قبل كل شيء**: اترك `gpt-5` بجهد `low` كما هو (وسط معقول)، أو عدّل `reasoning_effort` يدوياً في `server/hadithAnalysis.ts` إلى `"medium"` أو `"high"` إن قبلت بطئاً أكبر مقابل تحليل أعمق (أعد التوليد والدفع بعد التعديل: `pnpm run build:vercel`).

## 2) إنشاء قاعدة بيانات MySQL

المشروع يستخدم Drizzle ORM مع MySQL (`drizzle.config.ts`، `drizzle/schema.ts`). قاعدة البيانات **اختيارية للتشغيل** — التطبيق يعمل بدونها تماماً (السجل والمفضلة والملاحظات محفوظة محلياً في متصفح المستخدم)، ويستخدمها فقط جدول `users` عبر مسار تسجيل الدخول (`/api/oauth/callback`).

> **ملاحظة مهمة قبل الربط:** تسجيل الدخول الحالي مبني تحديداً على واجهة Manus OAuth (`server/_core/sdk.ts`)، وليس مزوّداً عاماً مثل Google. خارج منصة Manus لن يعمل تسجيل الدخول فعلياً حتى لو ضُبط `DATABASE_URL` و`OAUTH_SERVER_URL`، ما لم يُعَد ربط `sdk.ts` بمزوّد OAuth قياسي (تطوير إضافي، ليس مجرد متغير بيئة). فائدة ربط القاعدة الآن هي تجهيز البنية التحتية لهذا التطوير المستقبلي، لا تفعيل تسجيل دخول فوري.

### خطوات الإنشاء (PlanetScale — يعمل جيداً مع Vercel)

1. أنشئ حساباً على **planetscale.com** (له مستوى مجاني).
2. **Create a new database**، اختر أقرب منطقة جغرافية لمنطقة نشر Vercel (`iad1` = فرجينيا).
3. من صفحة قاعدة البيانات: **Connect** → اختر **Connect with: Node.js** → انسخ رابط `DATABASE_URL` الكامل (يبدأ بـ `mysql://`).
4. في Vercel: أضف `DATABASE_URL` بهذه القيمة، ثم Redeploy.
5. لإنشاء جدول `users` فعلياً على القاعدة، شغّل محلياً (بعد وضع نفس الرابط في ملف `.env`):
   ```bash
   pnpm run db:push
   ```

### بديل: Railway

1. أنشئ مشروعاً على **railway.app** → **New** → **Database** → **MySQL**.
2. من تبويب **Variables** انسخ قيمة `MYSQL_URL` (أو ابنِ الرابط من الحقول المنفصلة: host/port/user/password/database بصيغة `mysql://user:password@host:port/database`).
3. باقي الخطوات مطابقة لما سبق (اضبط `DATABASE_URL` في Vercel، ثم `pnpm run db:push` محلياً).

## البنية والنشر

- الواجهة والخادم التقليدي: `client/`, `server/` — يُبنيان بـ `pnpm run build` لاستضافة Node تقليدية (Railway/Render/VPS).
